### Patch 5 - Host-Save Hooks

Create `useDocxHostSave.ts`:

- owns `saveRequestTimerRef`
- owns `hostSaveInProgressRef`
- owns `hostSaveWaitersRef`
- exposes:

```ts
type UseDocxHostSaveOptions = {
    setDirty: (dirty: boolean) => void;
};

type UseDocxHostSaveResult = {
    hostSaveInProgressRef: React.MutableRefObject<boolean>;
    requestHostSave: () => void;
    requestHostSaveAndWait: () => Promise<void>;
    resolveHostSaveWaiters: (result: HostSaveResult) => void;
};
```

Keep validation at the WebView-host boundary. Do not add runtime validation around internal typed hook parameters.

Create `useDocxHostEvents.ts`:

- register `open`
- register `openBuffer`
- register `saveRequest`
- register `hostSaveCompleted`
- perform init retry

This hook will need many dependencies. If the dependency list becomes hard to audit, split save handling into `useDocxSaveRequest.ts`.

### Patch 6 - Document State, Dirty State, Mode, Keyboard, Timeout Hooks

Create `useDocxDocumentState.ts`:

- own the current `documentFile` memoization/update path,
- own edit buffer replacement after `openBuffer`,
- expose the current file object and buffer update API needed by the coordinator.

Create `useDocxDirtyState.ts`:

- own dirty-state mutation helper,
- own transaction/update dirty tracking,
- receive `readEditorTextSnapshot()` and snapshot comparison helpers as dependencies or imports from `docxSnapshot.ts`.

Create `useDocxModeSwitch.ts`:

- move `switchToViewer`,
- perform save-before-view transition,
- keep mode change behavior equivalent to the current toolbar path.

Create `useDocxKeyboardSave.ts`:

- move Cmd+S registration and cleanup,
- call the same host-save request path used by the toolbar.

Create `useDocxRenderTimeout.ts`:

- move render timeout effect setup and cleanup,
- expose the warning/error state needed by `Word.tsx` and `SuperDocSurface.tsx`.

Patch 6 is mandatory, not optional. Without it, `Word.tsx` keeps too much state/effect logic and may miss the under-350-line target.
